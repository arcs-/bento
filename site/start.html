Getting started

One script registers the elements. After that, a layout is markup: a group, its panels, and a separator between each pair you want to drag.

Install

bento will be published on npm as bento. It has no dependencies.

npm install bento

The package holds one file that matters, dist/bento.js. A public script URL, for loading it from a CDN, is not settled yet.

Load the script blocking in the head

Load the definitions as a plain, blocking <script> in the document head, before your app. The elements are then defined before the parser reaches them, so server-rendered panels lay out as they are parsed, and the first paint is already right in every browser.

Not type="module", not async, not defer: those run after parsing, when the page may have painted already. The script is small and cached after the first visit; inline it if you want no network wait at all. It carries its own styles, so there is no stylesheet to link, and it needs no Content Security Policy exception.

In a bundler, import "bento" registers the elements too. A module runs only after the document is parsed, which can be after the first paint, so keep it for apps that render on the client alone.

In Next.js and Nuxt

Next's <Script strategy="beforeInteractive"> runs before hydration but does not block. Put a plain <script> in the root layout's <head> instead, the way next-themes avoids its theme flash. In Nuxt, add the script to the head config; it renders as a blocking tag. Why the script must block

If you load it later

A page that loads the script late, for example with defer, would paint the panels unstyled first. Hide them until they are defined:

:is(bento-group, bento-panel, bento-separator):not(:defined) { visibility: hidden }

bento ships no document stylesheet, so this one rule is yours to write. Why there is no stylesheet

Three things to know from the start:

  • Every attribute is optional. A group of two panels and a separator, with no attributes at all, already splits the space equally and resizes.
  • Attributes are the starting state. Once the user drags or collapses, the live state is in the size and collapsed properties; the attributes stay as written. Why
  • Put one element inside each panel. It carries your padding and scrolling, like the .tray above. The panel itself is a layout box, and padding on it would stop it from collapsing.

Give the group a height, or put it in something that has one: a group fills its container's block size.
